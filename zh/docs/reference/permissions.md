# 权限矩阵

每个权限点、哪些内置角色持有它、它守着哪个菜单或 API。

权限点是夜莺权限模型的**第一层**。第二层是业务组成员关系，两层是 AND 关系：

```
能改这条告警规则  =  角色里有「改告警规则」这个权限点

                   且

                   我所在的某个团队，对这条规则所属的业务组有读写权
```

模型本身见[认证与权限模型](https://n9e.github.io/zh/zh/docs/concepts/auth-rbac.md)，这页只是查表用的清单。

## 三个内置角色[​](#三个内置角色 "三个内置角色的直接链接")

| 角色       | 覆盖范围                                                     |
| ---------- | ------------------------------------------------------------ |
| `Admin`    | 跳过权限校验，所有权限点都视为持有，也不受业务组成员关系限制 |
| `Standard` | 日常使用者。持有绝大多数权限点                               |
| `Guest`    | 只读旁观者。只有查询类的十几个权限点                         |

自定义角色在 **人员组织 → 角色管理** 里建，勾选需要的权限点即可。

一个用户可以同时持有多个角色，权限取并集。
