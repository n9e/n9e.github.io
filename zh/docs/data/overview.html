接入数据

夜莺在原地查询你的存储。十二种数据源共用一套规则体系；还没采集的部分交给 Categraf。

最后校对于 2026-10-10

把已有的存储接进来，夜莺在原地查询。指标、日志、SQL 类数据库用同一套规则体系，不必为每种数据源 重学一遍配法。数据不用搬迁：接数据源接的是一条连接，不是一份拷贝。

夜莺自身不做采集。推荐搭档是 Categraf——一个 agent、100+ 插件，按 Prometheus Remote Write 协议写入。Telegraf、Datadog Agent 和标准 exporter 以同样方式写入；已经在抓取目标的 Prometheus 也可以原样保留。

自动注册的内置时序库数据源

全新安装自动注册 embedded-tsdb 数据源（Prometheus 类型），Pushgw 收到的数据默认写入其中，查法与外置 Prometheus 相同。

Prometheus

注册 Prometheus 或 Thanos 地址，设置认证与超时，用一条查询验证。

VictoriaMetrics

VictoriaMetrics 按 Prometheus 类型接入，再把时序库类型设为 VictoriaMetrics；单机版与集群版的地址写法不同。

ElasticSearch / OpenSearch

接入 ES 或 OpenSearch 集群，选择索引模式与时间字段，跑一条日志查询。

ClickHouse / Doris / IoTDB

ClickHouse、Doris、IoTDB 同属 SQL 类数据源：查询结果的数值列成为序列值，其余列成为标签，直接用于告警判定。

Loki / VictoriaLogs

注册日志存储，写 LogQL 或 LogsQL 查询，按条数或匹配结果告警。

MySQL / PostgreSQL / TDengine

直接对业务数据库告警：只读账号、规则执行的 SQL、以及怎么防慢查询。
