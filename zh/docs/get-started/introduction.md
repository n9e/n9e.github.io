# 夜莺监控（Nightingale）是什么

夜莺监控（Nightingale，n9e）是开源告警引擎：接上已有的 Prometheus、日志库和数据库做规则判定、降噪和分发，自己不存数据、不做采集。

最后校对于 2026-10-12

夜莺监控（Nightingale，简称 **n9e**）是一个开源告警引擎，由中国计算机学会开源发展技术委员会（CCF ODTC） 托管，代码在 [GitHub](https://github.com/ccfos/nightingale)，Apache-2.0 许可。它不存你的数据，也不替你采集—— 它长在你已有的数据库之上，在其上做告警判定、降噪，把最后剩下的送到值班人手里。

## 它负责哪一层[​](#它负责哪一层 "它负责哪一层的直接链接")

| 层次                     | 夜莺                                                                |
| ------------------------ | ------------------------------------------------------------------- |
| 存储                     | ❌ —— Prometheus、VictoriaMetrics、ElasticSearch、ClickHouse 继续用 |
| 采集                     | ❌ —— Categraf、Telegraf、Datadog Agent、各类 exporter 都能写入     |
| **告警规则、降噪、分发** | ✅ **这一层才是它的主场**                                           |
| 仪表盘                   | ✅ 内置，但 Grafana 依然是一等公民                                  |

## 数据怎么流转[​](#数据怎么流转 "数据怎么流转的直接链接")

接一个数据源，在其上写一条规则，产生的事件依次经过屏蔽规则、订阅规则、事件 Pipeline，最后落到 通知媒介。v9 起同一个进程还是 MCP Server，AI 客户端可以用自然语言把这一整套跑通。

* **10+<!-- --> 数据源类型** —— 指标、日志、SQL 类数据库统一接入
* **20<!-- --> 份内置消息模板** —— 钉钉、飞书、企业微信、电话、短信、Slack、PagerDuty…… 其中 6 个媒介开箱即用，其余照模板填自己的地址
* **83<!-- --> 个内置集成模板** —— 采集配置、仪表盘、告警规则成套导入
