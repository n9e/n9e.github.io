# 用夜莺监控华为云

用华为云 cloudeye-exporter 把云监控（CES）指标转成 Prometheus 格式后抓取，模板覆盖 ECS、RDS、DCS、ELB、Kafka、RocketMQ、CSS 和 WAF。

最后校对于 2026-10-13

华为云的指标来自云监控服务（Cloud Eye）。华为云官方维护的 `cloudeye-exporter` 会按产品 namespace 把 CES 指标转成 `huaweicloud_sys_<service>_<metric>` 形式的 Prometheus 指标，用 Categraf 的 `prometheus` 插件抓取即可。

模板按产品分：ECS 主机、RDS（MySQL、PostgreSQL）、DCS Redis 的实例与代理节点、ELB、分布式消息（Kafka、RabbitMQ、RocketMQ）、云搜索（CSS/ES）和 WAF，每种一张仪表盘。规则覆盖 ECS CPU 与内存、RDS 连接与磁盘、DCS 内存与命中率、ELB 后端异常；指标说明逐条解释各产品的指标含义。

## 怎么接入[​](#怎么接入 "怎么接入的直接链接")

部署 [cloudeye-exporter](https://github.com/huaweicloud/cloudeye-exporter)，在它的配置里填 IAM 账号的 AK/SK、项目和要采集的 namespace。确认 `http://<exporter>:8087/metrics?services=SYS.ECS` 有输出后，用 Categraf 的 `prometheus` 插件按 namespace 抓取：

```
# conf/input.prometheus/huaweicloud.toml

interval = 120



[[instances]]

urls = ["http://<exporter>:8087/metrics?services=SYS.ECS,SYS.RDS,SYS.DCS,SYS.ELB"]

labels = { job = "huaweicloud" }
```

云监控指标粒度通常是 60 秒以上，采集周期不要短于它。

1. 在夜莺「集成中心」里找到 Huawei Cloud，把仪表盘和告警规则[导入到业务组](https://n9e.github.io/zh/docs/data/integrations/import.md)。
2. 导入的告警规则默认是停用的。先[确认指标已经入库](https://n9e.github.io/zh/docs/data/integrations/verify.md)，再按自己环境的阈值逐条启用。

### 华为云ecs cpu使用率大于80%[​](#华为云ecs-cpu使用率大于80 "华为云ecs cpu使用率大于80%的直接链接")

S2 警告 · 持续 1 分钟 · 触发条件:

```
huaweicloud_sys_agt_cpu_usage >80
```

处置步骤:

1. SSH 登录用 top -H 定位占用最高的进程与线程；
2. 用 perf top 或对应语言的 profiler 找热点函数；
3. 区分业务增长与代码异常（死循环、频繁 GC）；
4. 业务增长则在控制台变更为更高规格或做水平扩容。

### 华为云ecs inode已使用占比大于80%[​](#华为云ecs-inode已使用占比大于80 "华为云ecs inode已使用占比大于80%的直接链接")

S2 警告 · 持续 1 分钟 · 触发条件:

```
huaweicloud_sys_agt_SlAsH_disk_inodesUsedPercent >80
```

处置步骤:

1. 用 df -i 确认挂载点；
2. 逐层统计文件数找出小文件最多的目录；
3. 常见来源是日志碎片、session 文件、容器层，确认后批量清理；
4. 长期考虑把小文件业务迁到独立分区。

### 华为云ecs NTP偏移量大于1秒[​](#华为云ecs-ntp偏移量大于1秒 "华为云ecs NTP偏移量大于1秒的直接链接")


处置步骤:

### 华为云ecs TME\_WAIT状态的连接超过2万[​](#华为云ecs-tme_wait状态的连接超过2万 "华为云ecs TME_WAIT状态的连接超过2万的直接链接")

S2 警告 · 持续 1 分钟 · 触发条件:

```
huaweicloud_sys_agt_net_tcp_close > 20000
```

处置步骤:

1. 用 ss -s 看各状态连接数的真实分布；
2. 用 ss -tan | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn 定位连接对端；
3. 根因通常是短连接过多，应用侧改用长连接或连接池；
4. 应急可开启 net.ipv4.tcp\_tw\_reuse 并调大 ip\_local\_port\_range。

### 华为云ecs 僵死进程数大于0[​](#华为云ecs-僵死进程数大于0 "华为云ecs 僵死进程数大于0的直接链接")

S2 警告 · 持续 1 分钟 · 触发条件:

```
huaweicloud_sys_agt_proc_zombie_count >0
```

处置步骤:

1. 用 ps -ef | awk '$2 \~ /Z/ || $8 \~ /Z/' 或 ps aux | grep 'Z' 找出僵尸进程及其父进程 PPID；
2. 定位父进程后，问题在于它没有调用 wait()，需要在代码里修复；
3. 应急可重启父进程，僵尸会被 init 收养并清理；
4. 数量持续增长的必须修代码，重启只是临时手段。

### 华为云ecs 可用内存低于20%[​](#华为云ecs-可用内存低于20 "华为云ecs 可用内存低于20%的直接链接")

S2 警告 · 持续 1 分钟 · 触发条件:

```

```

处置步骤:


### 华为云ecs 发送误包率大于50%[​](#华为云ecs-发送误包率大于50 "华为云ecs 发送误包率大于50%的直接链接")

### 华为云ecs 磁盘写IOPS过高[​](#华为云ecs-磁盘写iops过高 "华为云ecs 磁盘写IOPS过高的直接链接")

