用夜莺监控 Kubernetes

抓 apiserver、kubelet、controller-manager、scheduler、kube-proxy、CoreDNS、kube-state-metrics 和 node-exporter 的原生 /metrics，模板覆盖控制面到 Pod 的每一层。

最后校对于 2026-10-31

Kubernetes 的每个组件都自带 Prometheus 格式的 /metrics，推荐用 Categraf 的 prometheus 插件直接抓取，再部署 kube-state-metrics（工作负载状态）和 node-exporter（节点资源）。旧的 Categraf kubernetes 插件已废弃，但模板里的仪表盘和规则照常可用。

数据源常用端点覆盖的模板
kube-apiserverhttps://<api-server>:6443/metricsAPI Server
kubelethttps://<node>:10250/metrics、/metrics/cadvisor、/metrics/resourceKubelet、Node、Pod、Container
kube-controller-managerhttps://<control-plane>:10257/metricsController Manager
kube-schedulerhttps://<control-plane>:10259/metricsScheduler
kube-proxyhttp://<node>:10249/metricsProxy
kube-state-metricshttp://<service>:8080/metricsDeployment、StatefulSet、DaemonSet、Pod 状态
CoreDNShttp://<coredns>:9153/metricsCoreDNS
node-exporterhttp://<node>:9100/metricsNode 资源

这是模板数量最多的一个集成：仪表盘覆盖控制面各组件、节点、Deployment、StatefulSet、DaemonSet、Pod、容器和 CoreDNS；规则覆盖 Pod 反复重启与 Pending、副本数不足、节点 NotReady 与资源压力、apiserver 延迟与错误率、etcd 与调度失败、证书到期；指标说明按组件逐条解释。

模板里有什么​

  • 17 张仪表盘，共 470 个面板
  • 154 条告警规则，每条附处置步骤
  • 305 条指标说明

怎么接入​

这类组件自己就暴露 Prometheus 格式的 /metrics，用 Categraf 的 prometheus 插件抓取即可，不需要专门的插件。如果你已经有 Prometheus 或 VictoriaMetrics 在抓这些端点，直接把它接成夜莺的数据源，模板同样能用。

控制面组件的端点需要 ServiceAccount token 或客户端证书，Categraf 以 DaemonSet 部署在集群内时用 bearer_token_file 读取挂载的 token。K3s 等发行版的 scheduler、controller-manager 和 kube-proxy 可能只监听 loopback，要在控制面节点本机采集；不要为了方便把这些无鉴权端点暴露到公网。

  1. 在夜莺「集成中心」里找到 Kubernetes，把仪表盘和告警规则导入到业务组。
  2. 导入的告警规则默认是停用的。先确认指标已经入库，再按自己环境的阈值逐条启用。
