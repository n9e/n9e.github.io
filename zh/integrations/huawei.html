用夜莺监控华为云

用华为云 cloudeye-exporter 把云监控（CES）指标转成 Prometheus 格式后抓取，模板覆盖 ECS、RDS、DCS、ELB、Kafka、RocketMQ、CSS 和 WAF。

最后校对于 2026-10-28

华为云的指标来自云监控服务（Cloud Eye）。华为云官方维护的 cloudeye-exporter 会按产品 namespace 把 CES 指标转成 huaweicloud_sys_<service>_<metric> 形式的 Prometheus 指标，用 Categraf 的 prometheus 插件抓取即可。

模板按产品分：ECS 主机、RDS（MySQL、PostgreSQL）、DCS Redis 的实例与代理节点、ELB、分布式消息（Kafka、RabbitMQ、RocketMQ）、云搜索（CSS/ES）和 WAF，每种一张仪表盘。规则覆盖 ECS CPU 与内存、RDS 连接与磁盘、DCS 内存与命中率、ELB 后端异常；指标说明逐条解释各产品的指标含义。

模板里有什么​

  • 14 张仪表盘，共 330 个面板
  • 35 条告警规则，每条附处置步骤
  • 286 条指标说明

怎么接入​

部署 cloudeye-exporter，在它的配置里填 IAM 账号的 AK/SK、项目和要采集的 namespace。确认 http://<exporter>:8087/metrics?services=SYS.ECS 有输出后，用 Categraf 的 prometheus 插件按 namespace 抓取：

# conf/input.prometheus/huaweicloud.toml
interval = 120

[[instances]]
urls = ["http://<exporter>:8087/metrics?services=SYS.ECS,SYS.RDS,SYS.DCS,SYS.ELB"]
labels = { job = "huaweicloud" }

云监控指标粒度通常是 60 秒以上，采集周期不要短于它。

  1. 在夜莺「集成中心」里找到 Huawei Cloud，把仪表盘和告警规则导入到业务组。
  2. 导入的告警规则默认是停用的。先确认指标已经入库，再按自己环境的阈值逐条启用。

内置告警规则​

共 35 条。每条给出触发条件（PromQL）和告警后的处置步骤，导入后可以直接改阈值。

华为云ecs cpu使用率大于80%​

S2 警告 · 持续 1 分钟 · 触发条件:

huaweicloud_sys_agt_cpu_usage >80

处置步骤:

  1. SSH 登录用 top -H 定位占用最高的进程与线程；
  2. 用 perf top 或对应语言的 profiler 找热点函数；
  3. 区分业务增长与代码异常（死循环、频繁 GC）；
  4. 业务增长则在控制台变更为更高规格或做水平扩容。

华为云ecs inode已使用占比大于80%​

S2 警告 · 持续 1 分钟 · 触发条件:

huaweicloud_sys_agt_SlAsH_disk_inodesUsedPercent >80

处置步骤:

  1. 用 df -i 确认挂载点；
  2. 逐层统计文件数找出小文件最多的目录；
  3. 常见来源是日志碎片、session 文件、容器层，确认后批量清理；
  4. 长期考虑把小文件业务迁到独立分区。

华为云ecs NTP偏移量大于1秒​

S2 警告 · 持续 1 分钟 · 触发条件:

huaweicloud_sys_agt_ntp_offset > 1000

处置步骤:

  1. 用 chronyc tracking 确认偏移与上游源状态；
  2. 华为云 ECS 建议使用内网 NTP（ntp.myhuaweicloud.com），确认已配置；
  3. chronyd 未运行的启动并设开机自启；
  4. 偏移过大用 chronyc makestep 强制对时。

华为云ecs TME_WAIT状态的连接超过2万​

S2 警告 · 持续 1 分钟 · 触发条件:

huaweicloud_sys_agt_net_tcp_close > 20000

处置步骤:

  1. 用 ss -s 看各状态连接数的真实分布；
  2. 用 ss -tan | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn 定位连接对端；
  3. 根因通常是短连接过多，应用侧改用长连接或连接池；
  4. 应急可开启 net.ipv4.tcp_tw_reuse 并调大 ip_local_port_range。

华为云ecs 僵死进程数大于0​

S2 警告 · 持续 1 分钟 · 触发条件:

huaweicloud_sys_agt_proc_zombie_count >0

处置步骤:

  1. 用 ps -ef | awk '$2 ~ /Z/ || $8 ~ /Z/' 或 ps aux | grep 'Z' 找出僵尸进程及其父进程 PPID；
  2. 定位父进程后，问题在于它没有调用 wait()，需要在代码里修复；
  3. 应急可重启父进程，僵尸会被 init 收养并清理；
  4. 数量持续增长的必须修代码，重启只是临时手段。

华为云ecs 可用内存低于20%​

S2 警告 · 持续 1 分钟 · 触发条件:

huaweicloud_sys_agt_mem_available < 20

处置步骤:

  1. 用 free -h 确认 available 与 swap 使用；

  3. 泄漏的在应用侧抓堆定位，不能只靠重启；
  4. 业务增长的在控制台变更为更大内存规格。

华为云ecs 发送丢包率大于50%​

S2 警告 · 持续 1 分钟 · 触发条件:

huaweicloud_sys_agt_net_dropout > 50

处置步骤:

  1. 用 ip -s link show 确认 TX dropped 的增长；

  3. 超限的在控制台调整带宽或变更规格；
  4. 未超限的排查安全组、内核发送队列与应用发送逻辑。

华为云ecs 发送误包率大于50%​

S2 警告 · 持续 1 分钟 · 触发条件:

huaweicloud_sys_agt_net_errout > 50

处置步骤:

  1. 用 ip -s link show 与 ethtool -S 确认错包计数；
  2. 云环境下物理层由平台负责，错包率异常应优先提工单给华为云；
  3. 同时确认是否为实例规格带宽超限导致；
  4. 有冗余的先把流量切走，避免持续影响业务。

华为云ecs 块设备使用率大于80%​

S2 警告 · 持续 1 分钟 · 触发条件:

huaweicloud_sys_agt_SlAsH_disk_usedPercent > 80

处置步骤:

  1. 用 df -h 定位挂载点，用 du -x --max-depth=1 找出占用最大的目录；
  2. 优先清理日志与临时文件，用 lsof +L1 检查已删除但未释放的文件；
  3. 在控制台对云硬盘做在线扩容，再用 growpart + resize2fs/xfs_growfs 扩展文件系统；
  4. 长期评估是否需要把数据目录迁到独立云盘。

华为云ecs 磁盘写IOPS过高​

S2 警告 · 持续 1 分钟 · 触发条件:

huaweicloud_sys_agt_SlAsH_disk_agt_write_requests_rate > 99

处置步骤:

  1. 用 iostat -x 1 确认实际 IOPS 与 await；
  2. 用 iotop -oP 找出写入最多的进程；
  3. 对照该云硬盘规格的 IOPS 上限判断是否已触顶——超高性能盘与通用型盘差异很大；
  4. 触顶的在控制台升级磁盘类型或扩容（IOPS 通常随容量线性增长），未触顶的优化应用写入模式。
