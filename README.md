# Nightingale website

The open-source website and documentation for [Nightingale](https://github.com/ccfos/nightingale),
served at <https://n9e.github.io>. Built with Docusaurus 3. English is the default locale at `/`;
Chinese is at `/zh/`. Chinese copy is the source of truth for wording, and the English copy is
written alongside it rather than machine-translated.

## Development

```bash
npm install
npm start                       # dev server for the default locale (English)
npm start -- --locale zh-Hans   # dev server for the Chinese site
npm run build                   # both locales: build/ (English) and build/zh/ (Chinese)
npm run serve                   # serve the build output locally
npm run typecheck
```

`npm run build` first runs the data scripts (see [Generated data](#generated-data)). If a fetch
fails, the build carries on with the data already in the repository.

## Deployment

Every push to `main` triggers `.github/workflows/deploy.yml`: it runs `npm ci && npm run build`
and publishes `build/` to the `gh-pages` branch, which GitHub Pages serves at
<https://n9e.github.io>. **Pushing to `main` is a production release.** The workflow can also be
run by hand from the Actions tab.

## Layout

```
docusaurus.config.ts   Site config: navbar, footer, i18n, analytics, the embed-mode script
sidebars.ts            Generated by scripts/scaffold-docs.mjs — do not edit by hand
docs/                  English docs
i18n/zh-Hans/          Chinese docs and theme strings
i18n/en/               English theme strings (navbar, footer, sidebar group labels)
src/
  content/             All homepage and landing-page copy (zh.ts and en.ts share types.ts)
  components/home/     Homepage sections and the shared home.module.css
  components/docs/     Components used inside docs pages (Shot, StackLayers, ...)
  pages/               Homepage plus the comparisons, integrations, download and Categraf pages
  css/custom.css       Design tokens, Docusaurus theme overrides, embed-mode styles
  clientModules/       Client-side hooks (Baidu Analytics pageviews on route changes)
  data/stats.json        GitHub numbers, refreshed by scripts/fetch-stats.mjs
  data/releases.json     Download page versions, links and checksums, refreshed by scripts/fetch-releases.mjs
  data/integrations.json Integration template catalog, refreshed by scripts/fetch-integrations.mjs
scripts/
  docs-tree.mjs        The docs information architecture: every page's title and description
  scaffold-docs.mjs    Regenerates sidebars.ts and the English sidebar labels from docs-tree.mjs
  integration-categories.mjs  Categories, hidden list, display names and search aliases for templates
  docs-env/            The screenshot environment for docs (see its README)
static/img/            Product screenshots, data source and channel logos, the user logo wall;
                       img/integrations/ holds template icons synced from upstream
```

## Editing copy

All visible homepage and landing-page text lives in `src/content/zh.ts` and `en.ts`. Both follow
the structure in `types.ts`, so a missing field fails `npm run typecheck`. Navbar and footer
strings for English are in `i18n/en/docusaurus-theme-classic/*.json`.

Writing or editing docs follows [WRITING-DOCS.md](./WRITING-DOCS.md). Adding a docs page means
registering it in `scripts/docs-tree.mjs` and running `npm run scaffold`.

## Generated data

The homepage numbers, the download page and the integrations catalog come from files in
`src/data/`, refreshed by:

```bash
npm run stats          # GitHub stars / forks / latest release
npm run releases       # release packages and checksums for the download page
npm run integrations   # template catalog; icons are re-downloaded only when their blob sha changes
```

Set `GITHUB_TOKEN` to avoid anonymous rate limits. When upstream adds a template that
`scripts/integration-categories.mjs` does not categorize yet, the script prints a warning and files
it under "Other"; the build does not fail.

## Design conventions

- Accent colors are only the product's own alert severity colors (S1 red / S2 orange / S3 blue),
  and they must carry real meaning, never decoration.
- The vertical rail beside the homepage's four stages is the severity bar from each alert row in the
  product, enlarged; at the step where data becomes an `event` it switches to the three severity
  colors, so the color change itself states a fact.
- Structural markers use object names that exist in the product (`datasource → rule → event →
  agent`), not 01/02/03.
- Motion is limited to one choreographed first screen (cards entering, the severity bar drawing,
  delivery channels landing in turn) plus hover states; all of it is off under
  `prefers-reduced-motion`.
- Product screenshots are the core visual asset. Light and dark versions switch on `[data-theme]`,
  not in JavaScript.

## Embedding in the product

The product's help drawer opens docs pages in an iframe with `?onlyContent&theme=dark|light`. In
that mode the navbar, sidebars, table of contents and footer are hidden, the theme follows the
parameter without being saved, and a trailing-slash URL is redirected to the slashless one. The
logic is `EMBED_INLINE_SCRIPT` in `docusaurus.config.ts`; the styles are at the end of
`src/css/custom.css`.
